# 渲染、手机验收与导出

## 1. 浏览器检查

每次前端修改后，至少截图检查封面、信息最密集页和末页。

使用目标锚点只显示一个分页，再截取固定坐标：

```text
http://127.0.0.1:PORT/index.html?v=REVISION#capture-5
clip: { x: 0, y: 0, width: 900, height: 1800 }
```

使用查询参数刷新缓存，避免旧 Logo 或旧 CSS 留在截图中。

不要依赖 `fullPage` 截图拼接固定分页。部分浏览器会在哈希目标、固定高度或背景图条件下重复页面。直接使用 900×1800 clip。

导航到目标锚点后等待字体、背景和 iframe 稳定，再截图。连续切换页面时立即截图可能捕获旧布局、重复内容或错误 iframe；必要时等待约 `300–600ms`，但仍以固定 clip 为准。

## 2. 图片格式陷阱

某些截图接口返回 JPEG 字节，即使保存路径后缀是 `.png`。拼接前检查：

```bash
identify output/page-5.png
```

若实际为 JPEG，先转码：

```bash
magick output/page-5.png output/page-5-real.png
mv output/page-5-real.png output/page-5.png
```

## 3. 手机端检查

生成 5 页横向 contact sheet 和约 216px 宽的单页缩略图。检查：

- 正文是否仍可辨认；
- 页面层级是否一致；
- 是否有过大的空洞或过密区域；
- Logo、金额、名额是否过小；
- 背景是否穿过正文；
- 首屏标题是否过高、过满或偏离左侧视觉轴；
- 末页 CTA 和二维码是否清楚。

手机缩略检查不能替代原尺寸检查，两者都要做。

## 4. 内容与品牌检查

- 文稿数字、日期、人数和金额与源文件一致；
- 删除项没有在其他版本中残留；
- 两个版本使用同一最终文案；
- Logo 使用最新、官方、高清版本；
- 中文字体没有拉伸；
- 乘号、时间轴圆点和对齐线处于真实视觉中心；
- 二维码可扫描，二维码下标签距离合适；
- 署名人员、组织前缀和顺序正确。
- 对改名类反馈执行全局检索，确认标题、正文、脚注、CTA、二维码 `alt`、两个版式和 Banner 中没有旧术语残留。
- 区分品牌联合锁定与单位罗列：封面 `品牌 A × 品牌 B` 可以表达联合发起；“联合主办”下面若只是罗列单位，默认不用 `×` 充当连接符。
- 奖品改为奖金时，同步检查“奖品/礼品/等值”“元/份”“总值”等相关词，并统一为现金金额、`元/人` 和奖金总额等一致语义。

## 5. 输出检查

交付前确认：

- 所有分页宽度完全一致；
- 署名 Banner 使用当前标准尺寸 `900 × 373px`；
- 完整长图高度等于分页高度总和加 Banner 高度，即 `页数 × 1800 + 373px`（若使用当前标准 Banner）；
- 完整长图没有重复页、空白条或横向偏移；
- 默认按完整分页拼接，不裁掉页首页尾的留白、纸张底色或呼吸区；“接缝自然”不是自动裁边的授权。
- 页面 1 和最终 Banner 都能完整显示；
- HTML 仍可直接编辑；
- 最终答复给出 HTML、完整长图、关键分页和 Banner 的可点击绝对路径。

## 6. 增量渲染与紧急交付

按反馈范围更新产物：

| 修改类型 | 必须重渲染 |
|---|---|
| 单页文案或排版 | 两个版式的对应分页、完整长图、contact sheet |
| 全局术语或字体 | 所有受影响分页、两个版式完整长图、contact sheet |
| Logo、二维码或合作伙伴 | 出现该素材的分页、完整长图、contact sheet |
| 署名或社交二维码 | 更新 HTML Banner、重新渲染 Banner、所有完整长图 |

用户明确表示即将发布时，保留三项最小验证：目标分页渲染成功、完整长图尺寸正确、旧术语检索为空。随后直接输出图片，不继续做非必要设计探索。
