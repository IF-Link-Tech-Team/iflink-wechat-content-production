# 微信公众号内容连续反馈处理手册

## 1. 先判断反馈影响范围

将每条反馈标为以下之一：

- **精确文案**：名称、句子、金额、日期、姓名、组织前缀。逐字采用。
- **全局术语**：群名、奖品/奖金、联合发起/联合主办等。检索所有 HTML、说明、脚注、`alt`、两个版式和 Banner。
- **局部视觉**：某页字号、Logo 大小、引号、时间轴节点。只修改对应结构，不顺带重排其他页。
- **流程回退**：用户否定上一轮方向时，恢复最近确认版本，不保留上一轮的裁切、缩放或折中补丁。

修改前列出受影响产物：HTML、具体分页、两版完整长图、contact sheet、Banner。修改后按同一清单更新。

## 2. 文案联动规则

- 一个术语出现多处时使用全局检索，不凭肉眼只改截图指出的位置。
- CTA 名称变化时同步修改标题、正文、免责声明和二维码替代文字。
- “奖品改奖金”属于语义迁移：同步修改奖品、礼品、等值、份数单位、最高金额和汇总标题。
- 用户给出最终句子时保留原标点和用词；不要把名词性短语改回不完整的定语。
- 合作单位展示区按语义排版：联合锁定标志可用 `×`，单位清单默认只靠间距罗列。

## 3. 排版反馈边界

- “字号大一点”只调整相关层级，不连带压缩边距或改变其他同级字号。
- “恢复原来排版”恢复行数、断句、对齐和留白，不只恢复文字内容。
- 中文装饰引号使用独立的上 `“`、下 `”` 元素，采用中文衬线字体；不把引号塞入正文首尾。
- 视觉对齐以墨迹边界为准；代码左对齐不等于光学左对齐，但未经用户确认不要过度补偿。
- 用户明确接受当前错觉或说“不修改”后，不再继续做光学微调。

## 4. 分页与接缝

- 每页保持 `900 × 1800`，默认完整拼接。
- 页首页尾的纸张底色和大留白属于版式节奏，不视为需要自动删除的“缝隙”。
- 不因聊天截图里有人认为分页不自然，就擅自裁短页面或压缩纵向留白。
- 只有用户明确要求“无缝版/裁切版”时才裁边；同时保留完整分页版，文件名区分清楚。
- 用户撤回无缝要求时，让主完整长图重新等于所有完整分页加 Banner 的高度总和。

## 5. 增量渲染

1. 修改 HTML 源文件。
2. 用查询参数和 `#capture-N` 打开受影响分页。
3. 等待字体、背景、Logo 和 iframe 稳定。
4. 截取固定 `900 × 1800` 区域并转成真实 PNG。
5. 同步更新 Bento 与非 Bento 对应分页。
6. 重新拼接完整长图并更新 contact sheet。
7. 若 Banner 变化，单独导航到 Banner 页面截取其真实尺寸；不要复用当前主页面截图变量。

避免快速连续导航后立即截图。页面未稳定时可能抓到旧布局、重复分页或把主页面误当 Banner。

## 6. 发布前快速模式

当用户说“马上要发”“直接输出”“不要过多检查”时：

1. 停止新增设计探索。
2. 完成用户点名修改。
3. 只检查目标分页能渲染、完整长图尺寸正确、旧术语无残留。
4. 直接返回最终图片和可点击路径，不输出冗长复盘。

快速模式减少检查范围，但不能跳过重新拼接，也不能只改 HTML 不更新图片。
