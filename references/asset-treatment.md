# Logo、二维码与合作伙伴处理

## 1. 素材优先级

1. 官方透明 SVG；
2. 官方透明 PNG；
3. 官方浅色/深色版本；
4. 从有色底图中提取；
5. 文字重建仅作为最后手段，且需用户确认。

不要用截图中的模糊 Logo 覆盖用户后来提供的高清矢量文件。

## 2. 光学边界

图片文件的矩形边界不等于 Logo 的视觉边界。检查：

- 左右透明或白色留白；
- SVG `viewBox` 是否远大于真实图形；
- 横向字标和方形图标是否按相同高度显得一大一小；
- 乘号是否位于两个 Logo 的可见墨迹中心。

先计算或观察可见墨迹边界，再决定 CSS 宽高。允许为单个 Logo 设置专用宽度、裁切容器、位移或 `viewBox`。

## 3. 浅色背景 Logo

- 优先透明底纯黑版本。
- 有透明通道的彩色 PNG：保留 alpha，只把 RGB 变为黑色。
- 白字叠有色底：按亮度提取白色前景为 alpha，再填充黑色。
- 黑字白底：将接近白色的背景转透明，保留黑色前景。
- SVG 尽量保持矢量；使用官方浅色底黑字版本，或在不破坏品牌规范的前提下使用 CSS 滤镜。

## 4. 多个合作伙伴

四个横向 Logo 不要硬挤成一排。优先：

- 2×2 网格；
- 整体靠左；
- 两列拥有一致起点；
- 每个 Logo 使用独立的光学校准尺寸；
- 放在背景干净区，不增加大面积白色承托层。

若背景器物仍影响阅读，先缩小网格宽度或移动到空白区，不直接覆盖器物。

## 5. 二维码

- 只裁取真实二维码，不重绘码点。
- 浅色区域使用黑码透明底；深色 Banner 使用白码透明底。
- 去掉装饰外框可以，但需保留足够 quiet zone。
- 二维码不能叠在声波、纹理或渐变强烈处。
- 输出后用真实手机扫描测试。

## 6. 署名 Banner

以下用于标准署名版。已有确认的活动专属结尾时在项目中延续，不强制改为黑底双二维码，也不据此改写通用模板。

- 当前标准署名 Banner 为 `900 × 373px`，采用黑底、左侧署名与 Logo、右侧双二维码及右下角社区介绍。
- 使用 [assets/credits-banner-template.html](../assets/credits-banner-template.html) 生成最终 HTML Banner；[assets/examples/IF.Link_推送banner_署名版_900px.png](../assets/examples/IF.Link_推送banner_署名版_900px.png) 作为视觉回归基准。
- 人员信息与二维码上沿大致处于同一高度。
- 平台名称位于二维码正下方并靠近二维码；通常 `6–10px` 间距足够。
- “微信公众号”“小红书”使用纯文字，不在前面添加项目符号。
- 官方 IF.Link Logo 位于左下，保留品牌口号。
- 当前示例使用纯黑底和白色文字；项目需要其他衔接方式时制作项目内变体。只有调整通用模板基线时才同步更新 HTML 模板与示例图。
